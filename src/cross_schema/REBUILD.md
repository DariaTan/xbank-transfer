# Пересборка xbank по карте FGW

`rebuild_xbank.py` применяет готовую карту `mbd_to_xbank` ко **всем строкам xbank**.
Для каждого поля MBD копируется указанная в карте колонка xbank. Один источник
может использоваться несколько раз. Поля с `null` получают `other_values_code`
своего энкодера из сохранённого `preprocessor.pkl` MBD-модели.

Результат предназначен для моделей CoLES/NEP/MLM с частотными энкодерами
`PandasDataPreprocessor`, обученных на адаптированном MBD. Формат файла —
`id, col_1, ..., col_16`: именно такие имена использует существующий
`data.mbd_adapter` при подготовке MBD для обучения. Соответствие полей слотам
берётся из `TRX_CATEGORY_MAP` того адаптера. Например:

| Поле MBD | Слот модели | Значение после пересборки |
|---|---|---|
| `src_type21` | `col_9` | Если пары нет — `other_values_code` энкодера `col_9` |
| `src_type31` | `col_13` | Если пары нет — `other_values_code` энкодера `col_13` |
| `amount` | `col_11` | Значения источника, указанного для `amount` в карте |
| `event_time` | `col_1` | Время из указанной колонки xbank |

`id` сохраняется из xbank. Дополнительные технические слоты `col_12`, `col_15`,
`col_16` заполняются нулями, как при обучении на адаптированном MBD: им вообще
не соответствуют поля MBD. Не путайте их с полями, оставшимися без пары в FGW.
Число строк и даты сохраняются; агрегации и случайной выборки нет.
Числовые значения копируются без нового масштабирования. Для отсутствующего
`amount` или времени выполнение останавливается: категориальный UNK для них
не определён. Категории сопоставленных колонок копируются без перекодирования
между банковскими справочниками; такую семантическую согласованность карта
колонок сама по себе не обеспечивает.

## Запуск

Из `xbank-transfer`, в окружении с зависимостями обучения, чтобы прочитать
сохранённый `PandasDataPreprocessor`:

```bash
PYTHONPATH=src python -m cross_schema.rebuild_xbank \
  --xbank-path data/xbank_data/trans_any_pos_anonym_encoded.parquet \
  --mapping data/profiles_vFGW/frozen_mapping.json \
  --preprocessor /path/to/mbd_model/preprocessor.pkl \
  --output data/xbank_mbd/transactions.parquet
```

Замените `/path/to/mbd_model/preprocessor.pkl` путём к препроцессору **той
MBD-модели, которую будете использовать на инференсе**. Коды могут отличаться
между полями и моделями, поэтому скрипт не подставляет произвольное число.
Нужна карта основного запуска xbank → MBD из корня `profiles_vFGW`, а не
карта из `testbed_folds` или другого тестбеда. `--testbed-only` такой карты
не создаёт.

При необходимости доступны `--threads`, `--memory-limit 16GB`, `--temp-dir`.
Обработка идёт через DuckDB, без загрузки всего датасета в pandas. Запись
сначала выполняется во временный файл; после проверки числа строк появляется
итоговый файл. Существующий выходной файл не перезаписывается.

## Передача UNK модели

`other_values_code` — **готовый индекс эмбеддинга**, а обычные значения в
сопоставленных колонках пока остаются сырыми категориями. Если снова пропустить
число UNK через частотный энкодер, оно может совпасть с обычной категорией
и превратиться в другой индекс.

Поэтому файл содержит Parquet-метаданные `xbank_mbd_transfer`: какие слоты
заполнены UNK, сами коды, размеры словарей, карту и SHA-256 препроцессора для
проверки происхождения файла. `data.loaders` и `data.splits` читают метаданные
при обычной и оконной загрузке. `build_ptls_records` применяет замороженные
энкодеры и затем восстанавливает UNK в отмеченных слотах. Перед этим проверяются
сохранённые коды и размеры словарей; повторное обучение препроцессора на таком
файле запрещено. SHA-256 сохраняется для аудита, при загрузке сравниваются
коды и размеры, а не хеш pickle.

Для инференса укажите новый Parquet как `transactions_path` и используйте
тот же MBD-препроцессор. Не теряйте метаданные при перезаписи файла.
При ручной загрузке в ноутбуке используйте `data.loaders.load_all_raw` или
`load_raw_for_clients`: обычный `pd.read_parquet` не выполняет наш перенос
метаданных в `DataFrame.attrs`. На сервер нужно перенести также новые
`data/transfer_metadata.py` и изменения `data/loaders.py`, `data/splits.py`.
Самостоятельность FGW-матчера и его флаги не меняются.
