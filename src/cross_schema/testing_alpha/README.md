# Проверка FGW коэффициента alpha

## Постановка

Проверяем восстановление соответствий колонок между **чистым MBD и зашумлённой копией тех же строк** при разных `alpha`.

- Данные: `detail/trx/fold=0/*.parquet`, до 2 млн строк
- Матчим 12 признаков: числовой `amount` и 11 категориальных. У копии колонки анонимизированы и переставлены, известное соответствие используется только для оценки.
- Используется исходный `match_schemas()` из `column_profiles_vFGW.py`: паспорта, структура `1 − NMI`, фильтры совместимости и semi-relaxed FGW. `alpha` задаёт вес структуры, `1 − alpha` -- паспортов. Одна исходная колонка может выбираться для нескольких целевых.
- На вызов FGW -- 5 инициализаций, максимум 300 итераций, `tol=1e-9`, `max_distance=0.70`. Seed выборки, перестановки и оптимизатора -- 42. Фильтры паспортов сохраняются и при `alpha=1`.

## Как добавляется шум

**Числовой признак:** для каждого конечного ненулевого значения независимо добавляем шум:

$x[r,j] = x[r,j] + \lambda \cdot s[j] \cdot \varepsilon[r,j]$, где $\varepsilon[r,j] \sim N(0,1)$.

Масштаб `s[j]` считается по чистой колонке: `Q95 − Q05`; при нулевом размахе -- `Q99 − Q01`, затем `max − min`. Нули, пропуски и бесконечности сохраняются; константные и бинарные числовые поля пропускаются. Значения после шума не обрезаются.

**Категориальные признаки:** каждое валидное значение с вероятностью `p` заменяется равновероятно на **другую** категорию из наблюдаемого словаря этой колонки. Новые категории не создаются; пропуски и поля с единственной категорией сохраняются.

| Условие | $\lambda$ -- числовой шум | p -- вероятность замены категории |
|---|---:|---:|
| `clean` | 0 | 0 |
| `mixed_015` | 0.15 | 0.15 |
| `mixed_030` | 0.30 | 0.30 |
| `categorical_015` | 0 | 0.15 |
| `numeric_015` | 0.15 | 0 |

Одна реализация шума используется для всех `alpha`. При одинаковом seed разные интенсивности используют те же случайные числа: числовые возмущения масштабируются, а маски категориальных замен вложены. Паспорта и NMI пересчитываются для каждой копии и переиспользуются при переборе `alpha`.

## Сетка запусков

| Сетка | $\alpha$ | Seed шума | Вызовы FGW | До инициализаций оптимизатора |
|---|---|---|---:|---:|
| Базовая, текущие локальные defaults | 0…1, шаг 0.1 | 0, 1, 2 | `(1 + 4 × 3) × 11 = 143` | 715 |
| Расширенная | 0…1, шаг 0.05 | 0, 1, 2, 3, 4 | `(1 + 4 × 5) × 21 = 441` | 2205 |

`clean` запускается один раз на `alpha`: seed шума не меняет чистые данные. Для расширенной сетки в `run.py` задаются `DEFAULT_ALPHAS = [i / 20 for i in range(21)]` и default `--noise-seeds = [0, 1, 2, 3, 4]` либо соответствующие аргументы командной строки. Условия шума заданы в `noise.py`, `NOISE_LEVELS`.

## Использованная команда

Из корня `xbank-transfer`:

```bash
PYTHONPATH=src python -m cross_schema.testing_alpha.run \
  --mbd-root /mnt/storage/d.tanyushkina/transactions/mbd_data/raw \
  --mbd-folds 0 \
  --out-dir /mnt/storage/d.tanyushkina/transactions/testing_alpha \
  2>&1 | tee /mnt/storage/d.tanyushkina/transactions/testing_alpha/log.txt
```

Команда берёт сетку из defaults `run.py` на машине запуска. Фактические параметры сохранены в `manifest.json`, размеры выборки -- в `sample.json`.

При новом запуске лог лучше писать **вне** `--out-dir`, например в `/mnt/storage/d.tanyushkina/transactions/testing_alpha.log`: `tee` внутри выходной папки может создать файл до инициализации эксперимента, а runner отклоняет непустую папку без `manifest.json`. При изменении сетки нужна новая папка результатов.

## Результаты

`results.csv` содержит метрики каждого запуска, `summary.csv` -- средние по seed. В `cases/` сохраняются восстановленные пары, диагностика FGW и `noise_audit.csv` с фактическими изменениями данных. Анализ -- в `results.ipynb`.

Точность -- доля правильно восстановленных полей из 12; незаполненные поля считаются ошибками. Отдельно оцениваются 11 категориальных полей. На графиках пять линий по условиям: среднее по seed и диапазон min–max. Эксперимент оценивает устойчивость к заданному шуму внутри MBD; оптимальность `alpha=0.5` заранее не предполагается.
